# Notifications first release

User requested inbox, optional phone push, fixture changes, fixture reminders, manager lineup reminders, and ladder challenges (received and deadlines). User preferences and Admin System controls. Inbox eligibility must be configurable by role; initial audience ONLY League Chair. No commits or pushes. User explicitly requires end-to-end implementation without intermediate approval.

Use database-backed inbox, preferences, global notification_config, subscriptions and outbox. Server authenticates every inbox/preferences/subscription operation and recomputes role eligibility from current active assignments (never client contexts). Feature enabled by default, eligibleRoles ['League Chair']; turning eligibility off immediately blocks inbox and delivery. Existing events not backfilled. Fixture recipients are affected active team players/managers plus active League Chairs for oversight (chairs currently global in app). Lineup reminder recipients managers plus chairs; ladder recipients actual challenger/challenged only, filtered by allowed role. All recipient role lookups include club_membership, team_membership and person_team_role. Active accounts/persons required. Chair doesn't receive unrelated ladder challenges.

Persist event notifications transactionally for fixture changes and challenge changes; reminders generated via CRON_SECRET protected worker. Dedup keys unique per person/event; fixture reminders keyed to schedule to allow new reminders after rescheduling. No expired reminder flood, no completed/cancelled fixture reminders. New ladder received events only on actual new challenge; deadlines for pending or accepted challenges. Inbox categories apply to future creation; push category selection independent, optional global push opt-in default false. Unread badge and inbox with mark read/all; tapping opens relevant destination. Account menu provides preferences. Visible-only 60s inbox refresh.

Admin System has role checkboxes, global/type switches, reminder offsets, Dublin quiet hours for push only, read-only VAPID readiness. Standard Web Push via web-push/VAPID extends existing sw.js. Keys stored only server environment; subscription per person/device, authenticated opt-in and opt-out. No permission prompt until user clicks Enable. iOS Home Screen guidance. Worker retries with backoff, deactivates 404/410 endpoints, skips read/expired/ineligible notifications. Push never required for inbox. Clicking opens same-origin deep link, never arbitrary remote URL. Do not send real user pushes while verifying. Add scheduler to deployment config; delivery requires deployment with VAPID env and cron.

Deployment follows the existing Hobby-compatible 24 daily scheduled jobs, distributed across hours. Fixture/challenge changes and self tests schedule immediate after-response push dispatch; hourly work handles reminders/retries/quiet-hour release. No new paid scheduler introduced. Timing is approximate on Hobby.
