# Targeted notification announcements implementation plan

User requests ability to compose a message and send notifications to role groups, a club, or a team within a club. Existing League Chair pilot remains in force. No commits or pushes unless newly requested. No real sends during implementation; use mocks, preview, rollback-only DB tests.

## Contracts
- Add notification type 'announcement' to policy, config/UI and user preferences. Config and Preferences gain version:2. normalize versionless settings appends announcement to inboxTypes/enabledTypes; pushTypes preserves prior choices (new category push defaults off). New default inbox/config includes announcement, default pushTypes original4. validate + returned values always version2 so deliberate announcement opt-outs persist. Existing role eligibility/global enabled/quiet hours remain enforced. Root owns policy, existing core createNotification/canDeliverPush integration if needed (same includes path handles new type automatically), notification-center UI categories and inbox deeplink.
- New migration supabase/notification_announcements.sql extends app_notification type check with announcement; adds notification_announcement(id uuid primary key client requestId, sender_person_id uuid ref, title text, body text, audience jsonb, summary jsonb, created_at defaultnow). RLS, revoke client roles. Root owns migration.
- Backend agent owns lib/announcement-policy.mjs + .d.mts pure validation/helpers, lib/server/notification-announcements.ts, app/api/admin/notifications/announcements/route.ts and tests. Root owns migration/policy integration. UI agent owns components/admin-notification-composer.tsx + integration under AdminNotifications outside settings form, tests.
- Draft input {title:string max120, body:string max2000, audience:{roles:string[] (empty means all roles),clubId:string|null,teamId:string|null}}. Clubs/team IDs validated UUID; team must belong selected club. Active assignments/accounts only, person dedup. Combined role+club/team filters intersect; roles themselves union, and manager/player role scoped to selected team/club. Use legacy team_membership and current person_team_role plus club_membership, club_admin, app_operator. No simulated/testUser access.
- GET /api/admin/notifications/announcements -> {clubs:[{id,name}],teams:[{id,clubId,name,league,season}],history:[{id,title,body,audience,summary,createdAt,senderName}],eligibleRoles:string[],enabled:boolean,announcementsEnabled:boolean}. Active current-season team options (or newest season if none active), no unrelated historical teams.
- POST {action:'preview',...draft} -> {preview:{matched:number,eligible:number,excluded:number,inbox:number,push:number,skipped:number,previewToken:string,enabled:boolean,announcementsEnabled:boolean}}. push count people (not devices), only prefs.pushEnabled+pushTypes announcement+active subscription. inbox honors prefs. Distinct roles memberships dedup. excluded means matched-eligible; skipped eligible with neither reachable selected channel.
- POST {action:'send',...draft,requestId:UUID,previewToken:string} -> {announcement:{id,...summary metadata},duplicate:boolean}. Backend recomputes audience/preferences snapshot; previewToken sha256 canonical validated draft + sorted reachable recipients (include perchannel decisions) + relevant config restrictions. If differs409 require re-preview. transaction atomic inbox/outbox/history, advisory lock by requestId, retries same ID return original record if same sender+payload; reject reused requestID with other sender/payload409. Dispatch scheduleNotificationPush() only after committed fresh send. Do not circumvent eligibility. Reject sends disabled/zero recipients clearly. Bulk insertion preferred to avoid per-person queries for all-player groups; reuse existing notificationAccess/normalized prefs/role conventions.
- Preview info and history in platform-admin only. Sending group notification is explicit admin composer Send button; implementation does not click Send against real recipients. New category href '/?notifications=1'; root will open inbox on that URL for eligible users. Expiry30 days. Plaintext React display, no arbitrary URL input.
